补跑了每种方法"每个框只给 1 个 class"的结果，下面一起解释。

## top-3 mAP50 是什么意思

计算 mAP 时，每个检测框要带一个 class 和一个分数。
- **1 class / box**：每个框只输出最可能的那个 class。这是 ultralytics 推理时的默认输出。
- **top-3**：每个框输出 3 个候选 class，分数 = 框的分数 × 这个 class 的概率。例如一个框 70 % 是电阻、25 % 是磁珠，就输出两个框："电阻，0.7" 和 "磁珠，0.25"。

mAP 是**每个 class 分开算 AP 再平均**的。所以多出来的低分候选在另一个 class 里只会轻微拉低 precision；但如果第二候选恰好是对的，那个 class 的 recall 就提高了。

## 它是我们自己凹出来的吗？

**不是新指标，但它确实偏向"会两边下注"的方法。**
- COCO 的评估协议本来就允许一个物体有多个不同 class 的检测框（每张图最多 100 个），很多 detector 也是这样输出的：Faster R-CNN 每个 class 单独做 NMS，DETR 从"query × class"里取分数最高的 100 个。据我所知，ultralytics 在验证（val）时算 mAP 也是用多 label 输出，只有推理（predict）时才默认每框 1 个 class。
- 比较是公平的：所有方法都用同一种格式，detector 本身也从 0.633 涨到了 0.664。
- 但是有偏向：概率分布越"犹豫"的方法，从 top-3 得到的好处越多。从下表可以看出，**B mix 在 top-3 下优势最大**。

## soft cascade C 的实现细节

**整体思路**：把原来流程里三个"硬决定"（选哪个文字、读成什么字、前缀对应哪个 class）全部换成概率，最后再相乘相加。不训练，也没有在 21PCB 上调任何参数。

### 第 1 步：输入
- **part**：detector 输出的框，分数 ≥ 0.25。每个框还带 detector 的 9 类分数，归一化后记为 **d_i(c)**。
- **text**：PP-OCRv6 检测到的文字框，**去掉落在元件框里 ≥ 50 % 的**（芯片上的型号字等）。KiCad 训练数据里也没有这类文字，所以这条规则让测试输入和训练一致。
- 每个文字框裁一小块图，送进 PARSeq（冻结的 OCR 模型），得到 688 维特征：前 8 个字符位置、每个位置 38 类的概率（结束符、0–9、A–Z 不分大小写、其他），记为 **Q[k, ·]**，再加上 384 维的编码器平均特征。

### 第 2 步：link 概率 a_ij
- LinkFormer（`v2d2_I_noise05_100k`，只用 KiCad 训练，训练时加入了 via、焊盘等噪声框）。输入是 part token（位置、大小）和 text token（位置、大小 + PARSeq 特征）。
- 输出每个 part 对"所有文字框 + none"的一行分数，做 softmax，得到：
  - **a_ij**：part i 的 label 是文字 j 的概率；
  - **a_i,none**：part i 没有 label 的概率。
- 保留 a_ij ≥ 0.005 的文字。

### 第 3 步：每个文字指向哪个 class，q_j(c)
用 PARSeq 的逐字符概率，算这个文字以某个前缀开头、后面跟数字的概率：

  **P(前缀 p) = ∏_{k < |p|} Q[k, p_k] × P(第 |p| 位是数字)**

例如 p = "FB"：第 0 位是 F 的概率 × 第 1 位是 B 的概率 × 第 2 位是数字的概率。

然后按固定前缀表（R → resistor，C → capacitor，FB / L → inductor，D / LED → diode，Q → transistor，U → IC，Y / X → oscillator，J / P / JP → connector，SW / S → switch……）把同一个 class 的前缀加起来：

  **q_j(c) = Σ_{p 属于 class c} P(p)**，  **q_j(∅) = 1 − Σ_c q_j(c)**

q_j(∅) 表示"这个文字不像任何已知的 designator"（例如读出 `015`、`GND`）。

### 第 4 步：合成
  **P_i(c) = Σ_j a_ij · q_j(c) + ( a_i,none + Σ_j a_ij · q_j(∅) ) · d_i(c)**

- 第一项：**link 到的文字说是什么 class**，按 link 概率加权。
- 第二项：没有 label，或者 label 读不出已知前缀，这部分概率**退回 detector**。
- linker 没看到的框（分数 < 0.25）直接用 d_i。

### 第 5 步：输出
每个框取 **argmax P_i(c)** 作为 class，分数 = 框分数 × P_i(这个 class)，再做按 class 的 NMS（IoU 0.6）。top-3 版本就是每个框输出前 3 个 class。

### 例子：R289（之前 B-head 判错的那个）
- link：R289 0.85，R290 0.08，R288 0.03，none 0.03。
- 三个文字的 q 都是 resistor ≈ 0.99。
- P(resistor) ≈ 0.85 × 0.99 + 0.08 × 0.99 + 0.03 × 0.99 ≈ 0.95；退回 detector 的部分只有约 0.04，所以 detector 的"capacitor 0.99"只贡献约 0.04。
- 结果：**resistor 约 0.95，判对**。

### C 的弱点（对应报告里的错误分析）
- **前缀表是固定的**：B、F、TVS、E 这类板子特有的前缀，q_j(∅) 很大，概率就退回 detector（32 个错误）。LLM 按板子补前缀表，正好修这个。
- **完全依赖 PARSeq 的逐字符概率**：倒着印或很小的字（`D15` 读成 `015`）会让 q_j(∅) 变大，同样退回 detector（50 个错误）。
- 退回 detector 时，C 和 detector 一样会犯外观上的错。

## 把 LinkFormer 的输出改成 AR prediction head

你的理解是对的，可以这样做：

| | 现在 | AR head |
|---|---|---|
| 输出方式 | 一次输出整个分数矩阵（parts × texts + none） | 每一步只决定**一个 part** 的 link |
| 唯一性 | 推理时用 Hungarian 后处理；C 完全没有约束 | 每选定一个文字，就把它标记为"已占用"，后面的步骤看得到 → **模型自己学会一对一** |
| 顺序 | 无 | 按置信度从高到低：先确定最有把握的 link（例如 R289 ↔ `R289`），难的留到最后 |

**具体实现思路**：
1. transformer 主干不变，得到 part token 和 text token。
2. 加一个小的 **AR 解码器**（1–2 层）：每一步，输入"已经确定的 link"（被占用的文字 token 加一个 "taken" 嵌入），输出下一个 part 对剩余文字 + none 的分数。
3. **训练**：teacher forcing，每块板子随机打乱 part 的顺序，或者按 GT 置信度排序，让模型学会在"部分文字已被占用"的条件下做选择。
4. **推理**：greedy 或 beam search，逐个确定。

**代价**：
- 推理变慢：一块板子有几百个 part，就要走几百步。可以每步确定一批高置信度的 link 来加速。

**Assistant** (15:00 UTC)

明白了，是 **causal（因果）MLP**。意思是：**每个输出只能依赖排在它前面的输出，不能看后面的**。这正是你说的"一个个判断"，也就是我表里的第 (a) 种：AR。

**常见做法有两种**：
- **加 mask 的 MLP**（例如 MADE）：把权重矩阵的一部分遮成 0，让第 k 个输出只接收第 1 到 k−1 个输入的信息。
- **causal attention**：transformer 里给 attention 加上三角形 mask，第 k 个 token 只能看前面的 token。GPT 这类语言模型就是这样做的。

**放到 LinkFormer 里**：
1. 把 part 排一个顺序，例如按 link 置信度从高到低。
2. 第 k 个 part 选 link 时，输入里包含前 k−1 个 part 已经选了哪些文字（被占用的文字会被屏蔽或加上 "taken" 标记）。
3. 这样第 k 个 part 不可能再选已被占用的文字，**一对一由模型结构保证**，不再需要 Hungarian 后处理。

**它的局限**就在"因果"这两个字：后面的判断看得到前面，但**前面的判断不能被后面推翻**。如果前面某个 link 错了，会把正确的 label 占掉，后面的 part 也跟着错（错误累积）。这就是为什么你前面想到"如果发现错了还能回去改"，那需要迭代修正或 diffusion，而不是纯 causal 的结构。

所以三者的关系是：
- **causal / AR**：保证一对一，不能回头改。
- **迭代修正**：保证一对一，能改，几轮就够。
- **diffusion**：保证一对一，能改，最重。

STATUS 里已经按这个顺序记下了，causal MLP 就是其中的 AR 选项。

**Assistant** (15:01 UTC)

一般的加法是：**主干不动，在后面加一个小的"因果解码器"作为新的 prediction head**。具体分 4 部分：

## 1. 结构

```
[现在的 LinkFormer 主干]  →  part 向量 h_i、文字向量 t_j、none 向量
            ↓
[causal 解码器，1–2 层]   逐步决定：第 k 步只为一个 part 选文字
            ↓
第 k 步的输出 = 这个 part 对"剩余文字 + none"的分数
```

**第 k 步的输入**：
- **query**：这一步要决定的 part 的向量 h_k（加一个"步数"嵌入）。
- **历史**：前 k−1 步的决定，每一步是一个 token：`part 向量 + 它选中的文字向量`（选了 none 就加 none 向量）。解码器对这些历史 token 做 **causal self-attention**（三角形 mask，只看前面）。
- **文字状态**：每个文字向量加一个 "**taken**" 嵌入，表示它是否已经被前面占用；分数计算时，已被占用的文字直接设为 −∞（硬约束），保证一对一。

**输出**：`score_kj = MLP(解码器输出_k) · t_j`，对"剩余文字 + none"做 softmax。

## 2. 顺序

- **推理**：先用主干现在的分数矩阵，按每个 part 的最高 link 概率从高到低排序。有把握的先定，难的最后定（这时候很多错误选项已经被占用了）。
- **训练**：用同样的规则排序，或者随机打乱顺序，让模型适应各种情况。

## 3. 训练（teacher forcing）

- "前 k−1 步选了什么"直接用 **GT 的 link**，所以所有步骤可以**并行**算（和 GPT 训练一样，靠 causal mask），不会比现在慢多少。
- 每一步算交叉熵，loss = 所有步骤的平均。
- 为了避免"训练时历史都是对的、推理时历史会错"（exposure bias），可以有一部分步骤用模型自己的预测代替 GT（scheduled sampling）。

## 4. 推理

- 逐步 greedy：一块板子有几百个 part 就走几百步，但每步只跑 1–2 层的小解码器，速度可以接受。
- 加速：每一步一次确定一批高置信度的 part（例如概率 > 0.9 的全部一起定）。

## 为什么没用

和前面的错误分析一致：
- **一对一冲突本来就不是主要问题**。原来的 Hungarian 已经保证了 hard link 的一对一；C 里两个 part 抢同一个 label 的情况本来就少。
- C 的错误主要来自**读字（50 个）和前缀命名（32 个）**，"link 到邻居"只有约 30 个，而且其中一部分是 GT 的问题。
- causal 结构"不能回头改"：前面拿错一个 label，后面就会连锁出错，抵消了好处。

所以如果要继续做结构化解码，应该选**能回头修正的版本**（迭代修正）；但从收益看，**优先做读字和前缀命名会更划算**。
