我查了一下，处理 rare class 的文章主要有三种报分方式：

**1. 长尾检测（long-tail detection，以 LVIS 为标准）**

LVIS 按每个 class 在**训练集**里出现的图片数，把 class 分成三组：rare（1–10 张）、common（11–100）、frequent（>100）。论文的主表一般报：

| 指标 | 含义 |
|---|---|
| AP（总体） | 所有 class 的平均 |
| **APr** / APc / APf | rare / common / frequent 三组各自的 AP，**APr 是主要卖点** |
| （有时）AP50、AP75 | 不同 IoU 阈值下的 AP |

例子：
- **Equalization Loss（CVPR 2020，LVIS v0.5，Mask R-CNN R50）：** AP 20.1 → 22.8，**APr 7.2 → 11.3**，APc 19.9 → 24.7，APf 25.4 → 25.1。也就是说，总分只涨 2.7，rare class 涨 4.1，frequent 几乎不变。这和我们的情况很像。
- **Seesaw Loss、EQL v2（CVPR 2021，LVIS v1）：** 报的也是 AP / APr / APc / APf 四个数，再和 baseline 逐项比较。

**2. 一个评测上的提醒（Dave et al. 2021，"The Devil is in the Details"）**

这篇指出，默认的 AP 可以被 "跨 class 重新排序" 刷高，所以提出 **AP_fixed**（让每个 class 的 AP 真正独立），以及检查校准的 **AP_pool**。这和我们发现的 "每个 box 给 top-3 个 class，detector 就从 0.541 涨到 0.602" 是同一类问题。所以论文里两种格式都要报，并且说清楚。

**3. 长尾分类（long-tailed classification）**

这类文章（OLTR，CVPR 2019；Decoupling，ICLR 2020）把 class 按训练样本数分成 many-shot（>100）、medium-shot（20–100）、few-shot（<20），分别报 accuracy，再报总体 accuracy。另一个常用指标是 balanced accuracy，也就是每个 class 的 recall 再平均。

**4. PCB 方面**

- 大多数论文只报 mAP50，加一个每个 class 的 AP 表。
- 有些文章明确提到 rare class 的问题，但没有专门的指标。比如 Data-Efficient Graph Embedding（2018）提到 resistor、capacitor 有上千个，switch 只有几个；V-PCB（2024）也说一些 class 很少见。
- 没有找到专门报 rare class 指标的 PCB 论文，这正好可以作为我们的一个贡献点。

|---|---|
| 主表 | mAP50、mAP50-95、macro-F1、**APr / APc / APf**。两种输出格式（每个 box 一个 class、top-3）都报 |
| class 判断（只看找到的 part） | 三组各自的 accuracy + balanced accuracy，对应长尾分类的报法 |
| 附录 | 9 个 class 各自的 AP |

## 页面怎么用

- **Space**：确认当前 part，跳到下一个没检查的 part。页面会自动放大到那个 part。
- **1–9**：改 class；**0**：ignore（test point、mech、fuse）。
- **L** 然后点一个文字框：把这个文字 link 到当前 part。link 到 BOM ref 时，class 自动改成 BOM 的 class。
- **N**：这个 part 没有 label。**D**：不是 part（删除）。
- **E / P / T**：拖动鼠标，分别是重画 box、补一个漏掉的 part、补一个文字框。
- 右侧可以直接改文字，用来修正 OCR 读错的字。下面列出这块板子上还没 link 的 BOM designator，方便你找漏掉的 part。
- 每个操作都会马上保存，我可以直接读到。Ctrl+Z 可以撤销本次打开页面以后的操作。
