2. Methods

All three use the same detector boxes; only the class decision differs. The linkers are trained on KiCad layouts only (no photos).

Detector (baseline)

Appearance only. Strong on R / C / IC, weak on rare classes that look like resistors.

C: soft cascade (no training)

Noise-trained LinkFormer (v2d2_I_noise05_100k) on the off-part OCR boxes; PARSeq character probabilities; fixed prefix table. The cleanest view of linker + OCR.

B-head: LinkFormer with a class head

The linker itself predicts the class. Its part tokens carry the detector's 9 class scores, so the head mixes appearance, label and context.

5. B-head: two key cases

B-head relies too much on the detector scores in its input. With the detector scores removed, the same model scores 0.801 on 21PCB (vs 0.793 with them; GT of 2026-10-19) but 0.554 on WACV (vs 0.641): on sharp labels the detector disturbs it, on blurry labels it needs the detector. Its training data (KiCad) has only simulated detector scores, which are almost never confidently wrong, so the head learned "a confident detector is right".

6. Caveats

  • The ground truth is the owner's: every box was kept, deleted, added or re-classed by hand. But the starting boxes came from this same detector, and about 92.5 % of the GT boxes keep the detector's geometry (IoU > 0.95, counted 2026-10-19). Box-level numbers (recall 0.86–0.89) therefore favour this detector. The three methods share the same boxes and differ only in the class, so the class comparison stands.
  • Rare classes are small (switch 13, oscillator 12, transistor 45): two new oscillator boxes alone lowered APr by about 0.04 on 2026-10-21.
  • Detector inference: each photo scaled so the median R/C is 29.2 px, then 1280-px tiles. Reading = PARSeq only.
