0. Names used on this page

  • linker: the transformer. Tokens = part boxes and text boxes. Output: which text belongs to each part (or none).
  • geometry: box size, shape and position. Every model has it.
  • G (geometry bias): extra attention bias from each pair of boxes (distance and size ratio measured in the box's own size).
  • S (string): the text token also gets the characters of the text, e.g. "C12" -> prefix "C" + digits "1", "2".
  • I (image): the text token gets a text-image feature instead: the crop of the text box goes through the PARSeq text reader, and its internal output (688 numbers) is added to the token. No OCR string.
  • class head: a trainable layer on each part token after the linker that outputs the part's class (9 classes).
  • prefix rule: no training. Take the linked text's letters and look them up: R -> resistor, C -> capacitor, ...

1. Model A: the best result so far (0.642 mAP50, needs perfect strings)

Model A = "GS" (G + S). The class is NOT learned: a fixed table does it. 0.642 needs the annotated strings; with real OCR strings the same model gives 0.58.

1b. Model I: image, link only (0.606 with annotated text boxes, 0.571 with OCR text boxes)

Model I differs from Model A in one place: the text token gets the image of the text instead of its string. The linker links with the image, but the class still comes from a reading of letters (here PARSeq's reading) through the same fixed table. So a misread letter still gives a wrong class; that is why Model I ends near Model A end to end (0.571 vs 0.582 with OCR text boxes). With annotated text boxes (the box drawn by a human, the pixels and reading still real): 0.606.

2b. Proposed: link first, then classify (class through the link)

Treat the link as a hidden choice. With link probabilities aij = p(part i -> text j) and ai,none:

p(class c of part i) = Σj aij · qj(c) + ai,none · ri(c)

  • qj(c): which class text j names (its letters), from the text-image feature; 9 classes + "not a designator".
  • ri(c): fallback class of a part with no text, from the part token (geometry; later detector class or part image).
  • Why the link head is "stricter": a link is right only for the exact text; the class is also right when the link goes to a same-class neighbour (C10 ↔ C11). So with right reading, class accuracy ≥ link accuracy, and the class must pass through the link.

Losses, all labels from KiCad: link loss (as now) + text-class loss on q_j (class of each text's prefix) + class loss on p_i (part class). At test: use p_i(c) directly (soft), or Hungarian link then argmax q of the linked text (hard). No fixed prefix table, no OCR string.

Pool, step by step (example: part i links to "C12" with 0.9 and "C13" with 0.1):

  • Link probabilities from the link head: a = 0.9 for C12, 0.1 for C13, ~0 for none.
  • Pooled text feature ti = 0.9 · hC12 + 0.1 · hC13: "what the linked text looks like". Both say "C" here.
  • The class head reads [hi (the part: geometry, context) ; ti (its text) ; ai,none (how sure it has no text)] and outputs 9 scores.
  • Part with no text: ai,none ≈ 1, ti ≈ 0, so the head must rely on hi; it learns this case from the none value.
  • Training: the class loss flows into the head, into ti, into the link probabilities and the transformer (end to end). The link loss keeps the link right; a small extra loss asks each text token to predict the class its letters name, so ti carries that class.

4. Where the possible gain is lost (mAP50)

Finding the text boxes costs ~0.03, reading the letters ~0.04. From 0.64 to 0.82: parts the detector misses or parts without printed text.

5. Noise boxes: teach the linker to say "none" v7

On WACV photos only 52 % of the OCR text boxes are labels: 23 % sit on a part (pad, body, value marking such as "103") and 25 % elsewhere (vias, pads, print such as "GND"). The KiCad training data had only labels, so the linker linked parts to these boxes.

  • Label box = the box of the designator printed on the silkscreen (e.g. "C12"). Model I gets only its geometry and the PARSeq feature of its image crop, never the string. The string is used only to build the training target (which part it belongs to).
  • noise R = each time a training board is drawn, R x (its number of labels) noise boxes are sampled from that board's pool (up to max(20, 2 x labels) boxes) and added as text tokens. A board with 40 labels gets 20 (R = 0.5) or 40 (R = 1.0). On WACV photos there are ~0.5 non-label OCR boxes per label after the rule, ~0.9 without it.

6. How mAP50 uses the box score v7

  • For one class, AP sorts every box predicted as that class by its score, high to low, and measures precision while walking down the list. A wrong box with a high score hurts more than one with a low score.
  • v6 and before: each box had ONE class. When the text changed the class, the box kept the detector's score, which is the detector's probability for its OWN class.
  • Better: score(box, class c) = P(there is a part) x P(class = c), with P(class) = (1 - p) x detector distribution + p x the text's class, p = link probability. Each box gives its top-3 classes. The detector's 9 class scores were recovered from the same model run.

  • Noise boxes help at 200k too: e2e link +12 points (all boxes), mAP50 top-3 +0.014, APr +0.03.
  • Distance rank features (rank of each text among a part's nearest texts, both ways, mutual nearest): +0.7 on clean41 but worse end to end; no help.
  • 200k overfits: training loss keeps falling (class loss 0.037) while clean41 and even KiCad val class accuracy drop (class head 91.0 % -> 89.4 %). The falling loss on wandb was the cosine schedule plus memorising, not under-training. 100k stays the recipe.
  • Board offset prior (test time: offset density of the confident links on the same board, k-means-like): accuracy goes down for every setting (I 92.9 -> 92.3 %, GS 93.6 -> 93.5 %); the linker already uses this regularity.
  • What blocks 98 % (GS 150k, clean41): 12 % of the labels are printed nearer another part ("messy"); accuracy on them is 75 % (47 % of all errors), on the others 96.1 %. Errors bunch on a few boards: DigitalDiscovery 54 of 191 labels wrong.

Seed spread (noise 0.5, 200k, seed 0 vs 1): clean41 link 0.8 points, e2e link (all boxes) 1.6 points, mAP50 top-3 0.004, APr 0.008. So noise + rank (0.670) vs noise (0.666) is within seed noise, and noise 1.0 vs 0.5 at 200k is a tie. wandb group v2d2_cls (runs replaycls-*), now with link / class loss logged separately.
