LinkFormer 模型图解

这是目前最好的 linker：XXL，1.16 亿参数，只在 KiCad 板子上训练过。下面说明它的输入、输出、置信度怎么来、loss 怎么算，以及漏连从哪来。 训练记录：wandb · crossclass / n2p8rs83（集群 job 200658）。

一句话

输入两组框：元件框和文字框。输出一张分数表：每个元件一行，每个文字框一列，再加一列 none（没印 label）。 每一行做 softmax 得到概率，最后用一对一分配（Hungarian）决定每个元件连哪个字，或者 none。下面先给全图，再用一块小板一步一步走。

跟着一块小板，一步一步看

下面这块板是我编的，只有 3 个元件、4 个文字框，单位是毫米。但所有输出数字都是真模型在这块板上跑出来的。 注意它本身就是 “元件和文字数量不一样” 的例子：3 个元件，4 个字，其中 TP1 是测试点，不属于任何元件。

第 0 步：一块板

第 1 步：每个框变成 4 个数（token）

先算这块板的 “尺子”：3 个元件长边分别是 2、2、6 mm，取中位数 2 mm 当作 1 个单位。这样大板小板都用同一把尺子。然后每个框（元件或文字）变成 4 个数：

第 1 个数 是不是文字：元件 = 0，文字 = 1 第 2 个数 ln(宽)，宽以 “单位” 计 第 3 个数 ln(高) 第 4 个数 宽 ≥ 高 吗：横着 = 1，竖着 = 0

第 2 步：4 个数变成 768 个数（嵌入）

每个 token 的 4 个数，经过同一个小网络（两层全连接），变成 768 个数。7 个框就是 7 个长度 768 的向量。这一步每个框各算各的，互相还不知道对方。

第 3 步：self-attention，框和框互相看

是的，就是普通的 self-attention：7 个向量放在一起（元件和文字混在一起，不分开），每个向量都看所有 7 个向量，包括自己。没有任何屏蔽，元件看文字，也看别的元件，文字也看文字。

“看” 的意思是：每个向量算出一个 权重，决定从每个别的向量里拿多少信息，权重加起来是 1；然后把拿到的信息加到自己身上。

a 对 b 的权重 ∝ exp( q_a · k_b / 8 ) q、k 由各自的向量算出来，每个 64 个数 a 的新向量 = a 的旧向量 + Σ_b 权重_ab · v_b

位置怎么进来（2D RoPE）。算 q_a · k_b 之前，把 q 和 k 按自己框的位置 “转一个角度”：一半的数按 x 转，一半按 y 转。两个转过的向量做点积时，剩下的只有两个框的位置差。 所以权重取决于 “b 在 a 的哪个方向、多远”，模型就能学到 “紧贴在我上方的小横框” 这种关系。

一层里有 12 组这样的 q、k、v（12 个 “头”），各自学不同的关系；一共叠 16 层。下面是第 1 层的真实权重（12 个头取平均），线越粗，看得越多：

第 5 步：一对一分配（Hungarian）

为什么需要。如果每个元件各自挑概率最高的字，两个元件可能挑中同一个字。看这个例子（数字是举例用的）：

字 T1字 T2none各自挑最大
元件 A0.700.200.10T1
元件 B0.600.100.30T1　← 撞了
元件 C0.050.150.80none

怎么做。规则是：每个元件选且只选一项（一个字或 none），每个字最多给一个元件，在这个前提下让三个概率乘起来最大（等价于 −log 概率加起来最小，这就是程序里的 “代价”）。几种合法的分法：

ABC概率相乘代价 = −ln
T1nonenone0.70 × 0.30 × 0.80 = 0.1681.78
T2T1none0.20 × 0.60 × 0.80 = 0.0962.34
T1T2none0.70 × 0.10 × 0.80 = 0.0562.88
noneT1none0.10 × 0.60 × 0.80 = 0.0483.04
T1noneT20.70 × 0.30 × 0.15 = 0.0323.46

最好的是第一行：A 拿 T1，B 只好 none，T2 没人要。B 这就是一个 “被分配挤掉” 的漏连。 板子大的时候（几百个元件）不可能把所有分法都试一遍，Hungarian 算法（1955 年的老算法，程序里用 scipy 的 linear_sum_assignment）能直接找到最好的那一个。

元件和文字数量不一样怎么办。做分配之前，给每个元件加一个它自己专用的 none 列，别的元件不能用。表就从 n × (m + 1) 变成 n × (m + n)：

字 R1字 C2字 U3字 TP1R1 的 noneC2 的 noneU3 的 none
元件 R10.992 ✓0.0000.0000.0010.007禁止禁止
元件 C20.0001.000 ✓0.0000.000禁止0.000禁止
元件 U30.0000.0000.626 ✓0.369禁止禁止0.004

这样无论数量怎样都能分：

• 字比元件多（这里 4 个字、3 个元件）：多出来的字没人要，TP1 就留空。这是允许的，板上本来就有不属于任何元件的字。

• 元件比字多（上面 A、B、C 的例子，3 个元件、2 个字）：每个元件至少还有自己的 none 列，所以永远分得完，多出来的元件得 none。

训练的时候不做这一步。训练的 loss 只看每一行自己的概率（见下面的 loss），一对一分配只在推理时用。

位置编码再说清楚：RoPE

你说得一半对。RoPE 输入的确是每个框自己的绝对位置：每个框按自己的 (x, y) 转一个角度。但注意力只用到 q·k 这个点积，两个都转过的向量做点积时，绝对角度消掉了，只剩角度差，也就是位置差。所以是 “绝对位置进去，相对位置出来”。

一维的例子（真模型里是二维，原理一样）：q 在位置 5，k 在位置 3，每个位置转 12°。

我们的实际设置。每个注意力头 64 个数，前 32 个按 x 转、后 32 个按 y 转，每边 16 对，每对一个转速。转速对应的波长从 0.5 到 512 个单位（对数均匀）：转得快的那几对对 “差半个元件” 很敏感，转得慢的对 “差几百个元件” 也有反应。 只有 q、k 被转，v（被拿走的信息）不转，所以每个框的向量里从来没有绝对位置。旋转、镜像整块板的不变性不靠 RoPE，靠训练时的数据增强。

尺度（密度）和信息量

密板和疏板。现在的做法是每块板用自己的 “尺子”：元件长边的中位数 = 1 个单位，所有宽、高、位置都除以它。这样一块 0402 电阻满板的密板，和一块全是插件的疏板，在模型眼里尺度差不多。这一步对照片也很重要，因为照片没有毫米，只有像素。

它的弱点在一块板上大小混在一起的时候：中位数由小元件决定，大元件（接插件、IC）的 label 通常离得远，按 “小元件单位” 量就显得特别远。漏连里大元件的比例是正常的两倍（35 % 对 15 %），这可能是原因之一。 改进方法见下面的 “按每个框自己的大小量距离”。

4 个数变 768 个数，信息够不够。嵌入这一步不会增加信息：4 个数进去，就只有 4 个数的信息。768 是模型的 “工作内存” 宽度，用来在 16 层里不断收集周围框的信息。 所以现在每个框自己带的信息确实很少（大小、方向、是不是文字），模型几乎全靠 “和谁挨着” 来判断。要提高，就是让每个框带更多信息：文字内容、元件类别、图像。

按实际能拿到的信息来设计

实际使用时，我们手上有：整张照片；检测器给的元件框（类别不准，不用）；所有文字框，每个文字框有一块图像，也有 OCR 读出来的字。逐项看值不值得放进 token：

推荐方案：按 LightGlue 的思路改造

我们的问题，和图像匹配里一个很成熟的问题几乎一样：两组点，一部分能配对，一部分配不上。图像匹配里是两张照片的特征点；我们这里是元件和文字。 这个方向最常用的方法是 SuperGlue（CVPR 2020）和它的后继 LightGlue（ICCV 2023），后者本身就用 RoPE。 我们现在的模型已经有一半是这个结构（Transformer + RoPE + 分数表 + 一对一分配），建议补上它的另一半，再加两个针对我们数据的设计：

下面逐个解释新增的四件事：做什么、用我们的例子说明、解决哪种错。

1. 元件可匹配度 σ：把 “有没有 label” 单独拿出来问

现在：“没有 label” 是分数表里的一列，和每个字一起抢概率。模型拿不准是哪个字时，概率分到几个字上，每个字都比不过 none，于是漏连（上面说的 “票被分散”）。

改成：拆成两个问题。σi 只回答 “这个元件有没有印 label”（0 到 1）；相似度只回答 “如果有，是哪一个”。例如 ATTIOT_Bottom 的 R48：现在 R48 0.32、C60 0.09、none 0.50 → 选 none。 拆开以后，如果模型认为 “有 label” 的可能是 0.8，那么在几个字里选最好的 R48 就行，不会因为票被分散而放弃。

none 的权重就在这里调。σ 用二分类的 loss 训练（有 label = 1，没有 = 0）。LightGlue 的做法是把正负两类的 loss 平衡：两类各占一半权重，而不是按数量。我们训练时 none 占约 30 %，平衡之后 none 不会因为常见而被偏爱。这就是你问的 “降低 none 的权重”，而且是以干净的方式做。

针对：漏连（WACV 157 个，占错误 41 %）。

2. 文字可匹配度 τ：这个字是不是元件编号

做什么：每个字也有一个 0 到 1 的分数：它是不是某个元件的 label。TP1（测试点）、GND、P2.3（芯片引脚名）、XMIN（功能名）都应该接近 0。

例子：上面那块小板上，元件 U3 给 TP1 分了 0.369。如果模型知道 TP1 不是元件编号（τ 接近 0），TP1 的配对概率就被压下去。这一项要靠 OCR 的字才学得好：光看几何，TP1 和 U3 长得一样。

针对：连到空闲字（80 个）和多连（102 个，影响 precision）。

3. 行、列两个方向的 softmax：训练时就让元件之间竞争

现在：训练时每个元件只在自己那一行里选（行 softmax）。两个元件都想要同一个字，训练时没人管，只有推理时的一对一分配才把它们分开。

改成：每个字也在自己那一列里，对所有元件做一次 softmax：同一个字被两个元件争，列方向就要分出谁更像。两个方向乘起来，模型在训练时就学会 “这个字离我近，但离你更近，那就是你的”。

例子：上面一对一分配那节的 A、B：行方向 A 对 T1 是 0.70，B 对 T1 是 0.60，都很高；列方向在 A、B 之间分 T1，比如 0.6 对 0.4。乘起来以后 B 对 T1 的分数明显降低，训练会推着模型把 B 的注意力转向别的字。

针对：抢邻居（142 个，占错误 37 %，KiCad 里也是 37 %）。

4. 几何偏置：按元件自己的大小量距离

现在：RoPE 用的是框的中心，单位是全板元件的中位尺寸。大元件的中心离它的 label 很远：一个 10 个单位宽的接插件，label 印在它右边缘外 2 个单位，中心到 label 有 7 个单位，在模型眼里 “很远”。

改成：在注意力分数上加一项，由这一对框的几何直接算出来：边缘之间的距离 ÷ 元件自己的宽高（上面的例子是 2 ÷ 10 = 0.2，“很近”），label 在元件的哪一边，两个框的大小比。几个数经过一个小网络变成一个分数，加到注意力上（Relation Networks、LayoutLMv2 都是这样做的）。RoPE 保留，两者互补：RoPE 管 “方向和中心距离”，这一项管 “贴不贴边、按谁的尺子量”。

针对：大元件漏连（漏连里大元件 35 %，正常 15 %），以及密度不同的板。

文字怎么编码，怎么防止 “太相信字”

每个 OCR 字拆成：前缀（R、C、J、U、TP…，查表成一个向量）+ 数字（每一位一个向量，右对齐）+ 置信度。这和以前试过的 E2 类似，但加三条防护：

• 模仿 OCR 读错：训练时随机把 0↔O、1↔I、5↔S、8↔B 互换，截掉最后一位（WACV 里常见，比如 R17x 读成 “R17”），加一个多余的字符。

• 随机去掉字：约 30 % 的文字 token 训练时不给字，只给几何，让模型缺了字也能连。

• 不让模型背编号：KiCad 里元件编号就是答案，模型看不到元件的编号（元件 token 不带字），只能从文字这边看。

每一步的数学

打分

文字分数 s_ij = ⟨W_q h_i , W_k h_j⟩ / √768 （元件 i 对文字 j） none 分数 s_i∅ = w · h_i + b （只看元件自己的向量） 概率 p_ij = exp(s_ij) / ( Σ_k exp(s_ik) + exp(s_i∅) ) p_i∅ = exp(s_i∅) / ( Σ_k exp(s_ik) + exp(s_i∅) )

文字分数是元件向量和文字向量的内积。none 分数只由元件自己的向量算出来，不和某一个文字比较（这个向量经过 16 层注意力，已经带着周围的信息）。每一行一共 m+1 个概率，加起来是 1。

训练的 loss

正确答案 T_i = 和元件编号相同的文字框（通常 1 个）；没有就是 {none} 单个元件 L_i = −log Σ_(j∈T_i) p_ij 一块板 L = 所有元件的 L_i 取平均；每步 4 块板

没有给 none 加权，也没有减权：答案是 none 的元件和答案是文字的元件，每个都算一份。但训练数据里答案是 none 的元件不少：

推理

一对一分配，见上面第 5 步。

为什么会漏连

漏连里 83 %（WACV）到 95 %（KiCad）是模型第一选择就是 none，不是分配造成的。原因有四个，前两个来自训练：

1. 训练里 none 很常见。约 30 % 的训练元件答案是 none，其中丢 label 那部分正好教模型：“自己的 label 不在附近，附近的字都属于别人，就答 none”。这和 WACV 里 label 印得远的情况长得很像。

2. KiCad 的 label 都贴着元件。KiCad 里连对的 label，到元件的边缘距离中位数是 0.05 个元件大小。WACV 漏连的 label 中位数是 0.55，44 % 超过 1 个元件大小。模型没见过多少 “远 label”。

3. 票被分散。none 只有一列，文字有很多列。模型拿不准是哪个字时，概率分到两三个字上，每个字单独都比不过 none。上面 ATTIOT_Bottom #76 就是这样：所有文字加起来 0.50，比 none 0.499 还多，但最好的 R48 只有 0.32。WACV 131 个 “想要 none” 的漏连里有 42 个属于这种。

4. 模型看不到字和类别。E1 只看几何，不知道 “J10” 和接插件配、“R48” 和电阻配。ATTIOT_Bottom 的接插件 J10，模型把概率分给了 TP99、两个 J10、C15，最后选了 none。

训练时降低 none 的权重，会怎样

如果把答案是 none 的元件的 loss 乘一个权重 w（w < 1），对 softmax 来说，效果大致等于推理时给 none 分数加一个偏置 log w。这个偏置我们已经试过（不用重训）：

做法相当于 wWACV 准确率WACV precisionWACV F1
现在190.9 %92.2 %0.916
none 偏置 −0.50.6191.7 %91.8 %0.917
none 偏置 −1.5（KiCad val 上 F1 最好）0.2292.3 %90.6 %0.915
文字概率加起来 > 0.5 就强制连（针对第 3 条）–91.8 %90.6 %0.912

都是准确率换 precision：漏连少了，但没印 label 的元件被连上字的情况多了，F1 基本不变。所以单纯降低 none 的权重，预计也是这个交换。

真正可能同时减少漏连、又不掉 precision 的训练改动：

• 少丢 label：数据增强从丢 15 % 改成 5 %，训练里 none 从约 30 % 降到约 22 %（针对第 1 条）。

• 给模型看字的前缀和元件的类别（E2 / E3 token），让它知道 J 配接插件、R 配电阻（针对第 4 条）。以前在旧数据上试过字符串，照片上变差了，CrossClass_data_v1 上还没试。

• 训练数据里多一些远 label：label 表、大元件（针对第 2 条）。
