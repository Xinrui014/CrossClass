## Findings worth keeping
1. WACV-clean v1 (tools/wacv_clean.py) raises every linker 1.2–1.7 points on the same 41 images; ceiling 100 %.
2. KiCad val 96.4 % → WACV 90.9 %: ≈ 2.6 points board density, ≈ 2.9 photo vs layout. 45 % of errors (both domains) are on labels printed
   nearer another part (KiCad: messy silkscreen, e.g. crossed or shifted labels; WACV: label tables).
3. None errors are the model's own "no label" choice (far labels, big parts, split votes); ≈ 30 % of training parts have a none target
   (18 % real + 15 % label dropout). Lowering the none score trades accuracy for precision (bias −1.5: +1.4 / −1.5).
4. Geometry measured in each box's own size (`--geobias`) is the first change that beats v1 (+1.3, precision also up).
5. LightGlue-style head (matchability σ/τ, dual softmax, balanced loss) trails the v1 head at small and full scale.
6. Strings: v2_S hit 98.0 % KiCad val but 88.8 % clean41 because data v1 never made JP / CN / LD / BTN / DS / RM / RP / T / F … footprints
   parts (kicad_links PFX exact list) → the model learned "these prefixes name no part" (115 of S's 174 new none errors).
7. Training speed: one board per forward left the GPU at ~38 %; per-forward overhead dominates, so 16 boards/step in one padded forward
   (token budget only) is ~2× faster per board than size-split groups and ~3× faster than v1's training; results identical.
